# 实机测试记录

这是严格名单诊断候选，完整在线对局尚未通过验收。当前 Payload 固定返回 `native_authority_admission_verified=false`，普通在线门禁必然阻断；本轮先执行版本、依赖与工具箱登录检查，并记录受管启动最后可达步骤。多人场景列出后续验收要求，当前记为 `BLOCKED`。打开工具箱、启动游戏、进入地图均不能代替角色出生和可操作验收。

每轮使用相同 `package_id` 的包。参与者用 A、B、C 标记，分别使用自己的 Steam 会话；不要共享账号、Token 或配置文件。三人测试应先让三人都进入待开始的房间，再冻结名单并开始，不能用虚构席位补足人数。

| 场景 | 实际操作与观察 | 通过条件 | 初始状态 |
|---|---|---|---|
| 版本与依赖 | 运行包内预检；核对包哈希、游戏构建和依赖 | 所有必需检查符合要求 | NOT_RUN |
| 首次启动 | 使用本包入口连接现有服务；正常登录 | 登录完成，房间列表可读取 | NOT_RUN |
| 游戏登录 | 通过工具箱正常启动，在游戏提示时按 SPACE 完成平台登录 | 游戏原生登录完成，不能仅记录 profile HTTP 200 | NOT_RUN |
| 两人完整开始 | A、B 先加入房间，按正常流程开始 | 两人均选角、出生并能正常操作 | BLOCKED：原生准入未验证 |
| 三人冻结名单 | A、B、C 都入房后开始 | 三人角色、队伍与席位一致，均可操作 | BLOCKED：原生准入未验证 |
| 延后连接 | 已在冻结名单内的一名玩家按协调员流程延后连接 | 仍按冻结的身份与席位接入，无额外席位 | BLOCKED：原生准入未验证 |
| 断开与重连 | 在允许的重连时间内断开再正常重连 | 正确恢复当前连接，旧连接不会继续生效 | BLOCKED：原生准入未验证 |
| 主机退出或切换 | 按协调员分配的 HOST 场景正常退出 | 房间和实例状态收敛，旧权限不再生效 | BLOCKED：原生准入未验证 |
| 结束与下一局 | 正常结束对局，再创建新一局 | 清理完成后实例才可复用，旧对局回执不影响新局 | BLOCKED：原生准入未验证 |
| 第二次冷启动 | 完全退出本轮游戏和工具箱，重新正常启动 | 登录和开始流程仍成功 | BLOCKED：原生准入未验证 |

结果只使用 `PASS`、`FAIL`、`BLOCKED`、`NOT_RUN`。部分步骤成功时，把整项记为 `BLOCKED` 并写明最后成功的步骤；未运行就保留 `NOT_RUN`。若缺后端、依赖、第二或第三台机器，注明缺少的条件。

当前已知问题：本开发机此前使用当前 Payload 和历史对照 Payload 的诊断均停在登录完成之前。此外，此包的普通路径受固定未验证标志阻断；其他机器出现 `native_admission_unverified` 是预期门禁结果，不能归因于其硬件或网络。记录代码和 UTC 时间后停止该轮，不重复点击开始或修改严格状态。

原生错误 audience、过期票据、重放等负例由协调员在受控环境单独执行。普通测试者不手改 Token、不执行控制台 `open`、不关闭严格名单，也不把未命中的拒绝场景标记为通过。
