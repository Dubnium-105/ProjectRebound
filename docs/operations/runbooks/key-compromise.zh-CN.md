# 签名密钥、中继 CA 或节点凭证泄露

[English](key-compromise.md) | 简体中文

1. 识别确切的凭据：管理员令牌、访问签名者、中继令牌签名者、中继 CA、节点令牌/证书、更新签名者或备份年龄身份。冻结相关版本并保留审计跟踪，而无需复制秘密材料。
2. 对于一个Relay身份，调用节点`revoke` API。它是不可逆的：控制流关闭，凭证被标记为已撤销，并且活动连接会迁移。使用新的节点身份重新注册。
3. 对于中继令牌签名者，暂存一个新密钥，等待每个 READY 节点的 Keyset 确认，激活它，并在最大令牌 TTL 内保留旧的公共验证密钥。如果私钥被主动滥用，则在运营商批准的情况下耗尽/撤销受影响的分配并缩短事件窗口。
4. 访问/更新签名妥协需要新的密钥 ID 和客户端/运营商分发计划。中继 CA 妥协需要新的 CA 并重新注册每个节点；普通的叶子更新是不够的。
5.轮换管理员和存储凭据，使暴露的 CI 机密无效，审核日志/提交/工件，并验证旧凭据是否被拒绝。更新加密的脱机恢复副本并完成恢复测试。

正常轮换详细信息见[密钥与证书轮换](../key-and-certificate-rotation.zh-CN.md)。
