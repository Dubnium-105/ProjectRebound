# 中继中断和迁移操作手册

[English](relay-outage.md) | 简体中文

在 `RelayNodeOffline`、`NoRelayAvailable`、高容量、BIND 失败、内存增长或迁移失败警报上触发。

1. 停止新的 Relay 版本。检查动态库存、容器状态、控制连接、心跳寿命、负载状态、容量、软件/协议版本、证书到期和活动分配。过时的数据库 `READY` 行并不能证明该节点在线。
2. 如果进程仍在运行，则允许其内置退避重新连接。不要重新启动运行正常或只是暂时断开连接的节点。如果进程不健康但可到达，则使用 `migrate_existing=true` 和有限的截止日期进行排空。不要一起重启一个区域中的所有节点。
3. 确认受影响的连接发出 `connection.relay_migrating`，接收新的参与者特定分配，并以 `relay_migrated` 或有界 `relay_failed` 结束。
4. 仅重新启动或回滚已确认停止的容器或活动分配为零的耗尽节点。它必须以 `CONNECTING` 重新连接，发出新的心跳，并在恢复/新调度之前到达 `READY`。如果其证书过期或身份被吊销，则停止重试并执行受控重新注册；永远不要复制另一个节点的身份。
5. 如果不存在目标，则增加容量或恢复节点；不要循环迁移。客户端必须显示失败的连接。
6. 比较之前/之后的分配计数并确认旧句柄不再转发。无需令牌或私钥即可保留中继/控制日志。

证书续签、监控字段以及连续在线长稳与故障注入的分离原则见 [Relay 连续在线与恢复](../relay-continuity.zh-CN.md)。
