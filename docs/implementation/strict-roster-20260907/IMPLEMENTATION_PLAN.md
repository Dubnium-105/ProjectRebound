# Codex 实施计划：直接完成权威名单唯一在线版本

**本计划替代前序“先保留旧在线流程再渐进迁移”的建议。用户已明确服务未正式上线，应直接完成权威名单版。**

## 0. 交付范围与基本原则

本轮交付的是实施计划，不是已实现代码。52项是去重后的工程项，包括确定缺陷、已定位缺口、条件性风险、产品/退役规则和验收门禁；每项有独立BP编号及AC验收。22个跨系统E2E场景补齐单项测试无法证明的链路。

不做旧在线兼容、不做长期新旧部署混跑、不以旧无名单房间救急。复用现有网络/数据库/签名/游戏原语，不重新拆更多微服务。明确模型后在当前两个仓库中完成同一版本的客户端、服务端、Payload和schema。

P0表示相关在线能力交付前的阻断，不表示该问题已在线上发生；P1是完整能力必须处理的可靠性/契约项；P2来源审计不在主要游戏修复关键路径，但若该二进制参与发布则来源不明必须阻断发布。

## 1. 实现目标

| 目标 | 验收结果 |
|---|---|
| G01 唯一在线权威 | 所有在线大厅/对局/玩家席位由MatchLobby/Attempt决定；不存在无名单直入、旧Meta独立匹配或旧房间业务旁路。 |
| G02 冻结名单不变 | 冻结后玩家身份、队伍和逻辑席位不可被网络连接、客户端报告或战绩重新定义；开局重试使用新Attempt。 |
| G03 原生准入真实生效 | 完成本机HOST身份、成员Grant注入、权威PreLogin验证和原生队伍/席位应用，不是仅安装签名JSON。 |
| G04 全流程可判定 | 异步operation_id贯穿启动，ProcessStarted/TransportReady/AuthorityReady/Admitted/WorldReady/Playable各有真实证据。 |
| G05 传输正确 | LEGACY_RELAY的直连/Relay与VNT只处理网络路径；多人数据不串线，迁移不改变名单或降低准入。 |
| G06 代次与撤销一致 | 会话epoch、名单版本、路线代次、授权代次和实际连接代次有独立含义；过期、撤销和旧事件不能复活权限。 |
| G07 失败可恢复 | 部分成功、取消、崩溃、超时和结束均可补偿；未清理的专服不重新分配；新对局不接收旧回执。 |
| G08 单一在线身份链 | 在线使用已验证的Go Meta适配和受管隧道；凭据刷新/持久化/重连统一管理，秘密不进入前端和命令行。 |
| G09 受支持前端语义一致 | 所有继续发布的前端消费同一业务控制器；停用旧入口可以，不允许留下一条无名单在线入口。 |
| G10 可审计交付 | 每个问题、改动、测试与产物有映射；实际三人以上游戏E2E与安全负向测试通过才可称权威名单版完成。 |

## 2. 不再实施的过渡方案

- 不开发旧房间目录与新大厅目录并存的在线产品。
- 不开发旧客户端/ACK/任意host:port启动的兼容代理或降级逻辑。
- 不把本地Node Meta继续作为在线身份链；它只可属于隔离的离线功能。
- 不允许旧Meta scheduler、BattleLog Presence、Connection回调各自决定同一新对局状态。
- 不以“strict flag保持false”“改成true即可”“先空token进场”作为最终功能完成。
- 不因为尚未上线就默认清数据库、强制重置工作区或公开私有源码。

## 5. 每个工程项的执行模板

1. **复核**：定位实际HEAD的对应路径/函数，记录是否仍成立。D/G也要复核；R先复现，C落实唯一目标下的规则，V建立真实验收。
2. **复现/测试**：先建立能证明缺陷或边界的用例；新功能缺口可先建立失败的契约/集成测试。测试样本使用合成身份和临时密钥，不放真实秘密。
3. **实现**：小范围修改既有模块，同步生产者与消费者。涉及DB时先列出全部写入口与租约/回收者。
4. **跨层验证**：Go→Rust、Rust→C++与实际原生事件分别取证；Mock和数据库直接调用不得替代更高层。
5. **回归与记录**：更新progress.json、对应AC/E2E、构建哈希和commit pair；任何未执行内容写NOT_RUN/BLOCKED。
6. **提交**：两个仓库分别提交相互匹配的变更，发布清单记录配对commit；默认不push/merge/部署。

## 6. 优先做的最小变更集合

先落地BP-001/BP-031基线和模型，再修BP-013/BP-022/BP-009/BP-024/BP-023/BP-025的协议与诊断，随后接入BP-016/BP-017统一启动。后端BP-033/BP-034/BP-048可并行提前修：网络提前RUNNING、投影反向推进、配置触发全库ABORT都是必须先隔离的风险。

这些补丁是直接目标版的基础，不是保留旧产品的第一期。新Lobby、在线Meta、Host/Member和原生准入按阶段继续完成；不得在“小补丁测试通过”后提前宣布全部联机已恢复。

## 7. 原生接入的工作拆分

**Policy与事务层：** 先完成BP-041/042的授权下界、幂等和预留/确认/释放，并用C++真实策略、Go事务测试交叉验证。把实际存活连接与授权代次分开，不通过机械赋值把旧连接标成新连接。

**客户端：** 验证锁定游戏中的合法Grant注入和登录触发；所有UE对象操作进入正确游戏线程。保留取消/超时和错误回执。在线Grant不能走命令行或前端。

**Authority/HOST：** 实际身份绑定、PreLogin、team/slot、原生连接事件必须执行；P2P HOST本地身份非空且匹配HOST席位，Dedicated玩家不走该特殊路径。未完成后端确认的连接不能成为可操作玩家。

**证据：** 每个接入点记录对应构建/游戏哈希与成功、拒绝、超时的实测轨迹。不要将已存在的bool、函数名、注释或提交说明当成验证结果。

## 8. 兼容的正确含义

此处仍需要“当前产物组合是否匹配”的验证，但不需要支持旧客户端。服务、Meta、Toolbox、Payload、游戏与schema必须配套；不支持的组合明确拒绝。老代码可删除，老数据默认保留，协议可直接升级。

现有安全边界必须保留：DPAPI、Ed25519清单和Grant签名、固定签名者/运行时校验、HMAC、防重放、SID/会话/PID归属、角色和节点凭据隔离。来源SOURCES.md中记录的路径用于定位，不是允许读取线上私钥。

## 9. Codex可自动执行与需外部环境的边界

| 工作 | 执行要求 | 缺资源时的处理 |
|---|---|---|
| 本地源码、分支、小提交、文档和测试编写 | 读取AGENTS，保留未提交改动 | 记录冲突，不强制reset |
| Go/Rust/C++测试和构建 | 使用仓库真实命令与锁文件 | 工具链缺失写BLOCKED，提供可运行命令 |
| PostgreSQL/Redis集成 | 隔离测试环境；明确实例标识 | 缺测试DB不得跳过后记PASS |
| Windows/真实游戏/平台身份 | 有授权的实际测试机与测试账号 | 实现harness和诊断采集；保留真实游戏验收阻塞 |
| 远程push/PR合并/部署/数据库重置 | 本计划不默认授权 | 单独提交操作范围再执行，不能把计划当生产批准 |

环境缺失不影响继续完成不依赖该环境的工程项。但原生真实验收缺失时，不可将对应功能标为已完成。

## 10. 最终交付清单

- 两仓库对应的实现commit和产物指纹；本机改动与新分支可审查。
- 更新后的OpenAPI/IPC/Relay fixture、目标状态机、凭据清单和支持的构建组合。
- 52项BP状态清单，每项对应AC，必要时对应E2E；R反证须有可核查依据。
- IMPLEMENTED.md：改了什么、在哪里、为什么；release-readiness.md：支持哪些模式、实际测试和剩余阻塞。
- E2E实际日志/回执/必要截图、资源趋势与测试运行环境；秘密必须脱敏。
- 旧在线入口/写者已退役的搜索与测试证据；未清理实例不回池；在线无隐式无名单回退。

**最终完成定义：所有声明支持的在线模式必须真实经过权威名单原生准入，玩家进入可操作战局，失败/取消可清理、重连有代次隔离、下一局无旧状态。52个条目都必须有明确处置，不能用“架构完成”“API已存在”“测试图通过”代替。**
